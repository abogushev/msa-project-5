## Детальный анализ

### 1. Конфигурация CRON-расписания
- **Apache Airflow**: Нативный поддержка CRON через DAG schedule_interval
- **Kubernetes Job**: Отличная интеграция с CronJobs в K8s
- **Spring Batch**: Требует внешнего шедулера (Quartz/Linux cron)
- **Apache Spark**: Нет встроенного шедулера, нужны внешние решения

### 2. Сложность реализации логики
- **Spring Batch**: Идеален для ETL-процессов, богатый набор процессоров данных
- **Apache Spark**: Мощные возможности обработки, но избыточны для задачи
- **Apache Airflow**: Хорош для оркестрации, но обработка через Python-операторы
- **Kubernetes Job**: Минимальная логика, нужно писать весь код с нуля

### 3. Ресурсоемкость
- **Kubernetes Job**: Запускается только на время выполнения, минимальные overhead
- **Spring Batch**: Легковесный, эффективное использование памяти
- **Apache Airflow**: Постоянно работающие компоненты (scheduler, webserver)
- **Apache Spark**: Тяжелый фреймворк, требует значительных ресурсов

### 4. Масштабируемость
- **Kubernetes Job**: Автоматическое масштабирование через HPA, легко масштабировать реплики
- **Apache Spark**: Встроенная распределенная обработка, горизонтальное масштабирование
- **Spring Batch**: Масштабирование через partitioning/chunking
- **Apache Airflow**: Масштабирование исполнителей, но сложнее чем K8s

### 5. Развертывание в облаке
- **Kubernetes Job**: Нативная интеграция с облачными K8s (EKS, GKE, AKS)
- **Apache Airflow**: Готовые managed-сервисы (Cloud Composer, MWAA)
- **Spring Batch**: Требует deployment приложения, интеграция через сервисы
- **Apache Spark**: Сложное развертывание, управляемые сервисы дороги

### 6. Логирование и мониторинг
- **Kubernetes Job**: Интеграция с Prometheus/Grafana через метрики K8s
- **Apache Airflow**: Встроенный UI, богатые возможности мониторинга
- **Spring Batch**: Spring Boot Actuator + интеграция с мониторингом
- **Apache Spark**: Spark UI, но сложнее интегрировать с централизованным мониторингом

## Рекомендация

### Kubernetes CronJob + Spring Batch

**Обоснование:**
- Сочетание легковесности и мощности
- Нативная CRON-поддержка через K8s CronJob
- Эффективная обработка 10k строк через chunk-и
- Отличная интеграция с микросервисной архитектурой
- Минимальное потребление ресурсов (запуск только при выполнении)
- Простое логирование через stdout/stderr в K8s
